    Detected providers¶

    This page describes the providers Pacto detected: the systems each source read evidence from, what Pacto uses each one for and how sure it is.

    The rows¶

    pacto fleet providers, GET /api/fleet/providers, the providers field of pacto_fleet_status and the Detected providers block on Data sources show the same rows. Each row carries id, source, cluster, name, evidence, usedFor, status and limitations, plus objects and objectsTotal when the evidence names objects. The evidence never names a namespace.

    Each cluster reports at least two rows, from two sources: the Kubernetes source (such as prod) and its workload source (prod-workloads).

    • Pacto CRD: served (pacto.trianalab.io/v1alpha1) or not installed. Pacto uses it for declared targets.
    • Kubernetes workloads: how many Deployments, StatefulSets, DaemonSets and CronJobs the workload source listed. A kind it could not list is unreadable, never 0, and one it listed in only some namespaces reads at least 12 Deployments (some unreadable). Pacto uses it for inferred services.
    • Argo CD and Flux: when the cluster serves their APIs, how many Applications (Argo CD) or Kustomizations, HelmReleases and GitRepositories (Flux) the workload source listed, such as 1 GitRepository, 1 HelmRelease or no Applications found. A kind it could not list is unreadable and the row partial. Pacto uses them for service grouping and repository provenance; see Groups and repositories. A cluster that serves neither shows no row.
    • Helm: how many Helm releases group at least one workload. Pacto reads no release Secret, so it uses them for service grouping only. When the workload read was cut short or a workload kind was unreadable, the row is partial.
    • Promotion: one row per promoter the installation names in its fingerprints and the cluster shows, by the API group of a CRD it serves or a label or annotation on a workload, such as promotion owned by Kargo (API group kargo.akuity.io served). Delivery reads promotion owned by <product> to know another tool promotes. When discovery fails, a promoter named only by its CRD shows a partial row that says Pacto could not check. A restricted view lists only the workloads you may list.
    • Reporting adapters: one row per adapter, signed or unsigned, that reports provisioning in the target-state file or signed envelopes, and one per producer the Evidence Server's trust config allows to report ResourceProvisioned or ResourceUsage, from the additive adapters list of its GET /api/evidence/v1/producers. Trust config rows show to every viewer, since that endpoint lists them to anyone.
    $ pacto fleet providers --k8s
PROVIDER              EVIDENCE                                             USED FOR
Pacto CRD             served (pacto.trianalab.io/v1alpha1)                 declared targets
Kubernetes workloads  412 Deployments, DaemonSets unreadable, 31 CronJobs  inferred services (partial: source prod-workloads could not list DaemonSets in any namespace: forbidden)

    With two or more clusters the table gains a leading CLUSTER column. With no row and no Kubernetes source it prints No providers detected: this view reads no Kubernetes cluster (add --k8s). When no source reported a service or a target, the answer's completeness is empty, so the CLI also prints warning: answer is empty on stderr while it still lists the rows.

    A row can carry offers: Pacto integrations that fit the detected provider, each with an id, a one-sentence text and a setup guide in doc. Pacto installs nothing. The Argo CD row offers "Gate every Argo CD sync with one repo-server plugin" (setup), which the CLI prints as an offer: line under the row and the dashboard as a Set up link.

    Fingerprints¶

    --fingerprints <file> on pacto fleet, pacto dashboard, pacto mcp and the other fleet commands, and the chart's fingerprints value, name the workload managers and promoters an installation runs. Each entry names a product and exactly one matcher: a fieldManager, label or annotation for a manager, and a crd (<plural>.<group>), label or annotation for a promoter. A file holds at most 64 entries. Pacto names no product in code: the chart's three defaults are entries of an open list, and a private IDP is one more. A promoter entry can also carry an offer (an id, a text that starts with "Gate every " and an https doc), which its row lists under offers; the Kargo entries offer "Gate every Kargo promotion with one shared AnalysisTemplate" (setup).

    managers:
  - product: Internal Deployer
    fieldManager: acme-deployer
promoters:
  - product: Kargo
    crd: stages.kargo.akuity.io
    offer:
      id: kargo-analysis-template
      text: Gate every Kargo promotion with one shared AnalysisTemplate
      doc: https://pacto.run/latest/integrations/kubernetes/gitops-kargo/#kargo
  - product: Kargo
    crd: warehouses.kargo.akuity.io
    offer:
      id: kargo-analysis-template
      text: Gate every Kargo promotion with one shared AnalysisTemplate
      doc: https://pacto.run/latest/integrations/kubernetes/gitops-kargo/#kargo
  - product: Argo CD Image Updater
    annotation: argocd-image-updater.argoproj.io/image-list
  - product: Flux ImageUpdateAutomation
    crd: imageupdateautomations.image.toolkit.fluxcd.io
  - product: Acme Release Train
    annotation: release-train.acme.example/stage

    A workload one of the managers applies reads external: <product> in the Stage applier verdict.

    Registry rows¶

    An OCI source adds one Registry <host> row per registry host it read a contract from. Pacto probes each host once per process, with the first contract it resolved there, and keeps the answer until the process restarts.

    • Evidence: what the probe saw, such as no Referrers, no _catalog or Referrers, _catalog.
    • Used for: native-referrers or write-once-tags, then index-listed-by-catalog or index-listed-by-tag. The CLI prints them with spaces.
    • Details: mode: referrers=<mode> listing=<mode>, the auth scheme of the /v2/ challenge, artifactType: not checked (read-only probe) and cosign signatures: not checked. Every detail says what was checked or that it was not. asOf is when the probe ran.
    $ pacto fleet providers --oci oci://ghcr.io/trianalab/pacto/postgresql:17.0.0
PROVIDER          EVIDENCE                   USED FOR
Registry ghcr.io  no Referrers, no _catalog  write once tags, index listed by tag

    The _catalog answer depends on the credentials the probe sends. The output above is anonymous. With a GHCR token, which Pacto finds through gh auth, GHCR serves _catalog with every public repository on ghcr.io, and the row reads no Referrers, _catalog and write once tags, index listed by catalog.

    A probe that cannot tell (a network error, a server error, an answer that is not an OCI index) is never a mode. The row then reads capabilities unknown, is partial and carries REGISTRY_PROBE_FAILED. A host whose contracts all failed to resolve has no row. A registry row never changes the answer's completeness. A restricted view drops a registry row when it hides every service read from that host. The delivery records reference explains what each mode means for records.

    Detected rows¶

    With --detected, the rows the operator detected in a cluster join from a source of kind detection: Registry, Cloud, Sign-in, Exposure, Metrics and Nodes. Each carries five more fields:

    Field Meaning
    provenance Always inferred
    asOf When the operator read it; older than 15 minutes is stale
    hint A command to review, set only when one candidate holds most namespaces. MCP omits it
    details Other candidates or facts, at most 5
    scope cluster for a row read cluster-wide

    Detected rows list after the rows a source reported. A detected row never clears a gate and never changes the answer's completeness. An entry the operator could not read is unavailable with a DETECTION_<KIND>_UNKNOWN limitation, and a partial one carries DETECTION_<KIND>_PARTIAL. A row naming a cluster no Kubernetes source of the snapshot reads carries DETECTION_CLUSTER_MISMATCH, and its source reads stale. A restricted view clears the evidence, hint and details of a row that names a namespace you cannot read, or of a cluster-wide row when you cannot read the cluster scope.

    Not read and not installed¶

    A cluster Pacto could not reach contributes no row. Every surface names its source as not read with the error, such as prod not read (connection refused). Only a cluster that answered without the Pacto CRD says not installed.

    A row is never healthier than its source. A row that is not available always carries a limitation that says why. PROVIDER_SOURCE_DEGRADED says so when the source itself is partial or stale, when the source marked the row partial without a reason or when a restricted view hid every other reason.

    Restricted views¶

    A restricted view keeps every row except a registry row whose every service it hides. Objects in namespaces you cannot read and cluster-scoped objects are hidden, as are limitations that name them, and so is the name of a cluster where you can see no target. A count stays only where you can read the namespace and list its kind there; a Helm release needs every workload kind. The rest becomes one hidden total, such as 12 Deployments (+30 hidden by your permissions). Hiding objects or counts never makes the answer partial.
