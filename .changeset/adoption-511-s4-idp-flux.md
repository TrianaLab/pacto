Deliver through the upstream Flux that IDP mode installs. Under `profile: idp`, the new chart value `idp.flux.install=true` installs upstream Flux 2.10.1 (source, kustomize and helm controllers, vendored and pinned under `files/flux/`, with the multi-tenancy lockdown) and upgrades it with the Pacto release; turning it off or uninstalling Pacto leaves Flux and its workloads running. Where no GitOps engine runs, Detected providers shows an Applier row that proposes that value. A Stage whose applier API is not served reads `Ready` `False` with the reason `NoApplier` and never promotes. The new `pacto.manifests` gate reads a version's Flux or Helm artifact before the promoter writes its pointer and refuses cluster-scoped kinds, objects outside the Stage namespace, RoleBindings to ClusterRoles and delivery, Flux or Argo CD objects; it judges every chart template as if it renders. Each refusal is a signed `apply-refusal/v1` record, listed beside refused publishes on `pacto delivery refusals`, `pacto_delivery_refusals`, `/api/delivery/refusals` and the dashboard, and `pacto delivery plan` lists the objects a promote applies. The inspector (`delivery.manifestInspector`, default `auto`) is now on for every delivery-enabled install, including upgrades; set `delivery.manifestInspector: false` to opt out.
