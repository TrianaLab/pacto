A hub lists the candidate clusters its Argo CD, Flux, Cluster API, OCM and Rancher already know, and hands out the install of the Pacto chart on every one of them through Argo CD or Flux. A person grants the reads with the new chart values `clusterInventory.enabled` and `clusterInventory.secretNamespaces`, both off by default: Secrets are listed as metadata only through a Role in each named namespace, and the inventory APIs only where the cluster serves them. The operator writes the candidates to the `clusters.json` key of its `<release>-detected` ConfigMap, and a Cluster inventory row on Data sources proposes the grant. Data sources (a collapsed Candidate clusters disclosure in the Clusters block), `pacto cluster list` and the MCP tool `pacto_cluster_list` show each candidate with its labels and source, to people who may approve clusterjoins. A candidate matches a member only by a cluster UID its object states, under the key a person approved; a pending member with that UID reads "states the same UID" and every other candidate "not matched", never merged by name. Environment labels of a matched candidate appear as inferred inventory environments on the member's join state and never reach a gate or placement. The new `pacto cluster install --from argocd|flux` prints an ApplicationSet or Flux HelmReleases whose values are only `registry` and `hub.url` when set; `--push` pushes them as one OCI artifact to `pacto-targets`, tagged by digest, and prints a Flux bootstrap that pins it. The dashboard downloads the same files with no `hub.url`. Removal orphans by default, and Pacto writes nothing to Git. The operator gains `--cluster-inventory`, `--cluster-inventory-namespaces` and `--chart-version`. The new [Install members](https://pacto.run/latest/install-members/) page shows the whole path. No contract field, `pactoVersion`, CRD or MCP tool changes.
