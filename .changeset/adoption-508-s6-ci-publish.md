`pacto ci --publish` publishes every changed service of a repository on the merged commit, providers first. An undeclared `service.version` is derived from the newest verified version in the registry and the change since it (`1.0.0` for a first publish), and a contract with no `publish` section gets one derived in memory: the image is built with the one tool the folder shows (Skaffold, ko, Jib, buildpacks or a Dockerfile), with no shell, and Pacto assembles the deploy artifact from the folder's manifests, Kustomization or Helm chart, with Secrets left out and the image pinned by digest. Signing is keyless by default, as the identity the GitHub Actions or GitLab `id_tokens` token names; a declared key or KMS key and `--sign-key` still sign with a key. Pull request pipelines and stale checkouts are refused, every tag is read back after it is written, a version lost to a concurrent run is planned again up to 3 times, and a failure blocks only the services of the run that depend on it. Each published bundle carries a signed record of the image digests its deploy pins. In `pactoVersion: "2.5"`, `publish.deploy` names a manifests or chart artifact any applier deploys and `publish.artifacts[].build` is optional and deprecated. `pacto init` and MCP `pacto_create` no longer write the shell publish section or the `service.version` placeholder. `pacto publish` gains `--image`, `--registry`, `--sign-key` and `--no-transparency-log`.
