# release/

The transaction-driven release pipeline for the Pacto monorepo. Full design +
invariants: [docs/maintainers/releases.md](../docs/maintainers/releases.md).

## Layout

- `release-manifest.json` — source of truth: release units, coordinates, versions.
- `release-plan.json` — derived plan (regenerated by `scripts/build-release-plan.mjs`,
  drift-gated in CI). `release-transaction.json` — what a release publishes, emitted
  only by `npm run release:version`.
- `scripts/` — the changesets/version tooling (`build-release-plan.mjs`,
  `apply-release-plan.mjs`) and the demo-bundle publisher.
- `orchestrator/` — the shared publish machinery, called by BOTH production
  (`.github/workflows/release.yml`) and the staging dry-run:
  - `detect.mjs` — decide release vs recovery from the transaction (fail-closed).
  - `ledger.sh` — durable, concurrency-safe per-unit OCI ledger.
  - `verify-oci.sh` — absent / identical / adopt / conflict for an OCI ref.
  - `publish-oci-unit.sh` — the crash-safe two-phase publish adapter.
  - `publish-go-tag.sh`, `build-cli.sh`, `finalize-release.sh`, `verify-artifacthub.sh`.
  - `dry-run.sh` — `make release-dry-run`: the whole transaction against a disposable
    local registry, only coordinates/credentials differ from production.

## Flow

Feature PR (+ a `.changeset`) → merge opens the **Version PR** (`release:version`) →
merging the Version PR publishes only the changed units, in dependency order, each
verified against the durable ledger. `workflow_dispatch` is recovery-only. There is
no separate "publish" command — production is `release.yml`, staging is
`make release-dry-run`.
