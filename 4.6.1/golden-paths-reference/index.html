    Golden paths reference¶

    This page describes how the operational graph treats golden paths and the services created from them. The operational graph reference covers sources and queries.

    Classification¶

    A golden path is a service the graph treats as a starting point for new services. A service is a golden path when:

    • the newest revision Pacto can read declares service.template;
    • the service has no operational target;
    • every source that reports targets (Kubernetes, the Evidence Server and a target state file) is available and complete, so Pacto knows the service runs nowhere.

    While such a source is unavailable or partial, a service without targets stays an ordinary service, so an outage never drops a running service from impact. A running service that declares service.template also stays a service and raises GOLDEN_PATH_DEPLOYED (warning, category golden-path). With no target source in the fleet, Pacto cannot tell a golden path from a service that runs elsewhere.

    A golden path's dependencies and references describe what services created from it need. They are never consumption:

    • impact, graph traversal, dependents, the neighborhood and offering consumers leave the path out;
    • the path has no offering membership and never joins OFFERING_CONFLICT;
    • the Overview service, owner, domain, readiness and attention summaries leave it out and count it in goldenPaths and invalidGoldenPaths; their links carry template=exclude, so a count matches its list;
    • an owner or domain that holds only golden paths has no row in the owner or domain list, and its own page still answers with zero services;
    • the path's detail lists the same edges as requirements, through the offerings they reach.

    Declared origins¶

    A service's origin is the service.origin of its newest readable revision. Pacto resolves it to the golden path revision whose content digest (lock.HashFS of the bundle, the digest pacto.lock records) or registry digest matches. An origin that matches no golden path, or more than one, keeps its ref and digest with a reason and links nowhere. Every origin is labelled declared.

    A service created from a directory records as ref the coordinate the path's publish.bundle and version name, which Pacto does not check against the registry. A path with no publish.bundle records a path relative to the new contract, or only the folder name when that path would climb above the home folder, so no host folder such as /Users/<name> is published.

    Filters¶

    Parameter Values Effect
    template (entities) only, exclude only keeps golden paths and, with no kinds, lists services only; exclude leaves them and their revisions out. Absent lists every service and marks golden paths template
    createdFrom (entities; MCP created_from) a service key, (none) or (unresolved) Keeps the services whose origin resolves to that golden path. (none) keeps the services that declare no origin and (unresolved) those whose origin resolves to no golden path in the view. A hidden, absent or non-path key answers an empty list
    sort (entities) created Golden paths that created the most services first, then the most non-compliant of those, then by name
    template (search) only, exclude The same filter on search; the default keeps golden paths, each hit marked template

    A golden path row in an entity list carries created, the number of services created from it, golden paths derived from it left out like the Services list leaves them out, nonCompliant, how many of those are non-compliant, and its signature status: not-checked when no source that read the path checks signatures, and the path's detail then has no signature.

    Services by golden path¶

    The aggregate of an entity list over services carries origins, which partitions the matched services that are no golden path by their declared origin, over the whole population before paging:

    Field Counts
    byPath Up to 10 golden paths, the most services created first, each with services, nonCompliant and hidden
    paths Golden paths that created at least one matched service
    beyond Services created from the golden paths past the ranking
    unresolved Services whose origin resolves to no golden path in the view (createdFrom=(unresolved))
    none Services that declare no origin (createdFrom=(none))
    hidden Services created from a golden path that the viewer cannot see, in no other count

    The services of byPath, beyond, unresolved and none sum to the matched services, and their nonCompliant counts sum to the non-compliant ones. pacto fleet entities prints the ranking under the list, and the dashboard's Golden paths page draws it.

    Creation checklist¶

    A service with an origin carries creation, a checklist derived from what the fleet holds. Each step is done only on its signal:

    Step done when Otherwise
    signature never unknown: a verified signature names a signer a publisher rule, pin or policy accepted, and an unverified one a signer none of them covers, which is no failure
    contract a revision was read
    validation the newest revision is valid with no *_UNVERIFIED or *_NOT_ENFORCED finding unknown listing those codes; failed when invalid
    plugin never unknown: Pacto does not observe what a plugin wrote
    published a registry served a revision unknown: seen only in local files
    fleet always, naming the sources
    deployed the fleet observes a target unknown
    provisioning every provider reports Ready failed on any Failed; unknown without reports; not-applicable when nothing provisions

    The delivery step appears only in the step list pacto init --from --delivery and pacto_create with delivery return. It is planned, then done, when the Pacto resource and every Stage were planned. Otherwise it is unknown with the reason.

    Golden paths in a restricted view¶

    A namespace-scoped viewer sees a golden path that has no Kubernetes target, like a declared offering provider, with only the revisions that declare service.template. Nothing in the view resolves to the older revisions it drops. Services created from it that the viewer cannot see are counted in hiddenCreated, and its requirements on services the viewer cannot see in hiddenRequirements, never named. A visible service whose golden path is hidden keeps its declared ref and digest and links nowhere, with the reason "the golden path it names is not in this view".
