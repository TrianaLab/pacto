Pacto Operator has been installed.

1. Verify the controller is running:

   kubectl get pods -n {{ .Release.Namespace }} -l app.kubernetes.io/name={{ include "pacto-operator.name" . }}

2. Install a Pacto contract:

   kubectl apply -f - <<EOF
   apiVersion: pacto.trianalab.io/v1alpha1
   kind: Pacto
   metadata:
     name: my-service
   spec:
     contractRef:
       oci: your-registry/your-contract
     target:
       serviceName: my-service
   EOF

3. Check contract status:

   kubectl get pactos

{{- if .Values.delivery.enabled }}

The Pacto delivery promoter is installed in {{ include "pacto-operator.delivery.namespace" . }}.
Keep that namespace writable by cluster admins only: anyone who can create a pod
there can act as the promoter or the recorder, and anyone who can edit its
ConfigMaps can change who counts as a person and which upstream keys are trusted.

It moves a Stage's pointer only through Operations. Admission lets it write
only spec.ref.digest, and only on an OCIRepository labelled
delivery.pacto.trianalab.io/apply-ref=<stage>, the label that also protects the
pointer from everyone else.
{{- if and (include "pacto-operator.delivery.argocd" .) (eq (toString .Values.delivery.argocd.enabled) "auto") }}

This cluster serves Argo CD Applications, so delivery.argocd.enabled=auto grants
the promoter patch on Applications. Admission limits that write to
spec.source.targetRevision of Applications labelled
delivery.pacto.trianalab.io/apply-ref. An upgrade that takes the new chart's
defaults, such as --reset-then-reuse-values, on a cluster with Argo CD grants it
too. Set delivery.argocd.enabled=false to keep it off.
{{- end }}

Agents run as their own ServiceAccounts: bind {{ include "pacto-operator.delivery.fullname" . }}-agent
to them. People who may update a workload (the built-in edit or admin role in its namespace)
approve its changes. Then:

  pacto delivery plan --namespace <ns> --stage <stage> --to sha256:<digest>
